# ClockoutHQ working instructions

This is the consolidated Clockout workspace. All project subfolders are part of this repository; do not initialize nested repositories.

- Start with the root README, then read only the relevant subfolder instructions and current context.
- Load the global `$codex-quota-optimizer` skill for tool-using work under the global activation rule. Use Context Mode to keep bulky tool output out of context. [Token Optimizer](https://github.com/alexgreensh/token-optimizer/blob/86e2daa524def9613199a1291c3c81a94adaa0bb/docs/codex.md) is optional for manual reporting. Use recorded Codex token counts to evaluate session usage and keep its automatic hooks disabled.
- For business context, read `Clockout Context/docs/AGENTS.md` and the current state and checkpoint files it identifies.
- For every local website project, start with the [website sales operating system](Clockout%20Context/docs/04-offers-and-sales/website-sales-operating-system.md) and follow its playbook and project form for the current stage.
- For website prospects, prepare a two-page brief and stop at the [founder approval gates](Clockout%20Context/docs/07-tools-and-systems/execution-system.md#demo-authorization-and-enforcement). Obtain explicit approval before constructing any website or reusable master template. Pilot preview publication, outreach and production launch each have separate approvals. Keep execution on hold until applicable controls are verified.
- For a fresh ClockoutHQ 2.0 chat, start with the [canonical handoff](Clockout%20Context/docs/CHECKPOINT.md#current-implementation-handoff--2026-11-07-u09--d23) and use the [implementation roadmap](Clockout%20Context/docs/09-execution-and-decisions/clockouthq-2-0-implementation.md) and linked specifications. The documentation scope does not authorize Phases 2–6 or any protected action.
- For toolkit setup or stage-specific website skills, use the [toolkit rollout in the tool register](Clockout%20Context/docs/07-tools-and-systems/tool-register.md#toolkit-rollout-plan) and check the recorded trigger before installing a deferred tool.
- For voice work, read `donovin-clockout-brand-voice/AGENTS.md` and its referenced profile/workflow files.
- For sales, cold email, local business, SEO, web design, or related work, search `Reference Library/INDEX.md` for relevant saved sources, then read only the matching records. Follow `Reference Library/AGENTS.md`. Cite useful sources when applying their advice; treat it as attributed reference, not adopted Clockout policy.
- Founder review documents are planning and evidence; distinguish proposals, simulations, historical facts, and current owner decisions.
- Old repository URLs, source paths, and public-visibility descriptions in copied files are historical. Use this private repository and these local subfolders for ongoing work.
- Keep credentials, private client records, local tool state, and caches out of Git.
- Preserve unrelated work. Update the canonical document for the task and verify relevant changes.
- Commits, pushes, repository deletion, and other external changes require applicable user authorization.

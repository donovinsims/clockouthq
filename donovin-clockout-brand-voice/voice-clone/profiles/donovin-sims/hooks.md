# Donovin hooks and structures

Corey's [hook research](../corey-ganim/hooks.md) remains attributed association-based evidence. Historical performance does not predict Donovin engagement. Use both typical and stronger non-held-out examples.

## Adapted hook families

- **Task relief:** name a repetitive task, then a specific way to make it easier.
- **Show the workflow:** describe the input and useful output, then give the steps and check.
- **Counterintuitive process:** identify the bottleneck before suggesting a tool.
- **Bounded build:** give an agent one job, explain the review point and failure case.
- **Real reflection:** a supported background fact plus an original present-tense perspective; no invented personal scene.
- **Transparent calculation:** label hypothetical inputs and show the arithmetic. Never open with invented earnings.
- **Tool connection:** explain an application and tradeoff. Verify current features through official documentation before publishing tool-specific instructions.

For A: task → worked example → repeatable steps → independent check.
For B: operational leak → diagnostic evidence → proposed fix → adoption/measurement.
For threads: useful promise → connected stages → example → limit → next action.
For articles: concrete problem → framework → detailed worked examples → constraints → optional genuine resource.

## Original illustrative openings

These are generated construction examples, not Donovin-authored historical posts:
- “Give your next AI workflow a finish line.”
- “Before connecting another tool, write down who owns the handoff.”
- “Start an agent with the task you can check in one minute.”

Build a fresh angle for the brief. Do not recycle these openings mechanically or lift reference anecdotes. Boldness without useful mechanics is just hype. No universal hook formula, forced CTA, celebrity-access story, income headline or guaranteed virality.
